# NAZO FORGE — 上級者向け謎解きトレーニング（フェーズ2）

高難度のオリジナル謎を解き、観察・表象転換・論理・情報統合を練習するGitHub Pages対応アプリです。**難しいと実測確認された問題集ではなく、上級・超上級として制作した候補を公開する段階**です。既存商用公演の問題文・図柄・固有の仕掛けをコピーしていません。

## 今回の収録状況・品質ゲート

| 区分 | 件数 | 扱い |
|---|---:|---|
| 公開する上級候補 | 11 | ゲーム内で出題 |
| 公開する超上級候補 | 13 | ゲーム内で出題 |
| 内容が単純すぎるため保留 | 6 | データは `src/data/challenges.ts` にあるが、ゲームには出題しない |
| 旧版の初級〜超上級 | 100 | `archive/legacy-100/` に退避し、ゲームでは出題しない |

**合計：公開24問（候補30問を作成、うち6問を保留）。** 100問を無理に維持せず、解きごたえを優先しました。除外候補：F005 / F006 / F010 / F012 / F029 / F030。`src/data/index.ts` の `DEFERRED_IDS` で出題対象を制御します。旧問題の初見記録を誤って新問題の記録として扱わないよう、新しい問題ID（F001〜F030）を使用しています。

現在の問題は **作者側の机上検討＋機械的整合性テスト** の段階です。別解の有無、難易度、初見での納得感を作者以外の人に検証してもらう工程は未実施です。現段階で「全24問が上級者にとって難しいことを検証済み」とは言えません。

## モードと主な操作

- **5分トライアル：** 10問（上級6問＋超上級4問）、回答済みを保持、時間切れで自動終了、終了後に解説
- **自由トレーニング：** 10/20/50/100/無限（50・100を選択しても現在は最大24問）、ジャンル・難易度選択、3段階ヒント、誤答再入力、スキップ
- **実力測定：** 初見問題のみ、最大20問、20分。途中で正誤や解説を表示しない
- **復習：** 誤答・ヒント使用・スキップ・ブックマーク・90秒以上かかった問題から再挑戦
- **キーボード：** Enterで回答、Alt+←/→で問題移動、Hでヒント（練習・復習）、Bでブックマーク、Escで拡大画面を閉じる
- **操作性：** 問題ナビゲータ、誤答履歴、図の拡大・縮小、回答欄へのフォーカス、状態表示、スマホ画面対応
- **学習記録：** ブラウザのlocalStorageに記録。他の端末には同期しません。記録のバックアップ出力に対応しています

専門分野の知識を問うのではなく、問題に示された規則の発見・組み合わせを意図しています。高難度化を単なる計算量・文字数増加で代用していません。

## 問題の追加方法

1. `src/data/challenges.ts` に新しいIDで問題の本文・図・解答・ヒント3件・解説4項目を追加
2. `src/data/index.ts` で公開対象に含まれることを確認（保留の場合は `DEFERRED_IDS` へ追加）
3. `npm test` を実行し、正答と図の座標・条件の整合性をできるだけ `tests/` に追加
4. 初見プレイヤーに解いてもらい、別解・不明瞭さ・難易度を確認してから公開
5. `npm run build:pages` で `docs/` を更新し、ソース一式とともにGitHubへ反映

問題の評価詳細は `QUALITY_AUDIT.md`、検証結果は `VERIFICATION.md` を参照してください。

## いちばん簡単な GitHub Pages 公開手順

**このソース一式のZIPを使う場合**：

1. ZIPを展開します。`src/`、`docs/`、`README.md`などを含むフォルダーの**中身すべて**がリポジトリ直下に並ぶようにします。
2. GitHubで既存のリポジトリ `nazotoki-doujyou` を開きます。
3. リポジトリの `Add file` → `Upload files` から展開済みファイルをアップロードしてコミットします。Gitを使う場合もリポジトリ直下に配置してください。
4. リポジトリの `Settings` → `Pages` → `Build and deployment` → `Source: Deploy from a branch` を選びます。
5. `Branch: main`、フォルダー：**`/docs`** を選び、`Save` します。
6. Pagesに表示される公開URLを開き、トップページ・1問挑戦・回答・ページ再読込を確認します。

一般的なURLは `https://<GitHubユーザー名>.github.io/<リポジトリ名>/` です。公開URLはGitHubのPages画面に表示されるものを優先してください。

> GitHubへ直接commit、push、公開設定変更・デプロイは実施していません。上記は利用者が操作する手順です。

## ローカルで動かす

Node.js 20.19以上または22.12以上を推奨します。

```bash
npm install
npm run dev
```

ターミナルに表示される `http://localhost:5173/` などをブラウザで開きます。

データ編集後、GitHub Pages用の **`docs/`** を更新するには：

```bash
npm run build:pages
```

`npm run build:pages` はTypeScriptを `docs/assets/*.js` にコンパイルし、参照パスを変換してCSSとSVGを同梱します。Vite向けビルドも `npm run build` で用意しています。GitHub Pages用の確認済み成果物は `docs/` です。

自動テスト：

```bash
npm test
```

Python PlaywrightとChromiumが利用できる環境では、任意でブラウザ操作テストを行えます。

```bash
python tests/run_browser_smoke.py
python tests/run_browser_esm_smoke.py
```

`run_browser_smoke.py` はCommonJS化したブラウザ操作テストです。`run_browser_esm_smoke.py` は **GitHub Pages用に生成されたJavaScript** を、モジュールの import 文を保持したままBlob URL経由でChromium内に読み込み、画面・操作が動作することを検査します。これらはHTTP経由の実公開サイトそのものを検証するテストではありません。

`npm test` には、公開用 `docs/assets/` 内で相対参照する JavaScript ファイルがすべて実在するか調べる再発防止テストが含まれます。

## 公開後に画面が真っ黒な場合

1. GitHub Pages の Source が `main` / `/docs` であることを確認してください。
2. `docs/assets/main.js` の `from './data/index.js'` が正しく記載されているか確認してください。以前のビルドで誤った `./data.js` を出力する不具合があり、2026-11-06に修正しました。
3. 変更後は `npm test` を実行し、`docs/` をコミットして公開し直してください。
4. すでに公開したGitHub Pagesでは、公開が反映されてから `Ctrl+F5` で再読み込みしてください。

## 問題の追加・修正

問題データは `src/data/` に難易度別で分離されています。`PuzzleRow` の形式で、ID／ジャンル／問題文／表示データ／正解／ヒント3段階／解説4項目／許容回答／視覚問題フラグを定義します。

- 既存IDと重複しない問題IDを付ける（例：`A31`）。
- 問題文に正答を紛れ込ませない。図・ヒント・解説が同じルールを使っているか確認する。
- `src/data/index.ts` の集約先に含まれているか確認する。
- `npm test` と `npm run build:pages` を実行する。
- 公開前に人間が初見で解いて、難易度や曖昧な別解を確認する。

## 回答・成績の扱い

- 回答はUnicode NFKC正規化、英字大小・ひらがな／カタカナ・空白除去を行い、各問題が持つ正答・許容回答だけに照合します。あいまいな類似度による自動正解は行いません。
- 端末の `localStorage` に初回挑戦日、正答・誤答、履歴、ヒント、スキップ、ブックマーク、セッション結果、自己ベストの算出元を保存します。別端末・別ブラウザへの自動同期は行いません。
- 保存形式はバージョン1。解釈できない旧版・破損データが見つかった場合、上書きを避けて通知します。プレイ中データだけが不正な場合はセッションを破棄し、保持できる成績を残します。
- サイトは外部API・ユーザー登録・バックエンドを必要としません。画像は同梱のSVGとブラウザ標準の絵文字・図形です。

## 注意と制作状況

- **100問はすべて登録され、問題画面で表示できる形式です**。ただし、プログラム上のチェックは謎そのものの面白さや解法の一意性を完全には保証しません。
- 上級・超上級問題の実際の正答率、想定所要時間、初見難易度は複数人のプレイテストで検証する必要があります。
- 外部公演への参加・公式コンテンツの再現を目的としたものではありません。
- 実施済みテストの詳細と未検証項目は [VERIFICATION.md](VERIFICATION.md) を参照してください。
